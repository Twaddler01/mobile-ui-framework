* `core/` must not depend on the DOM or Phaser. This keeps component definitions and builder portable.
* DOM is the default renderer. It gives normal scrolling, responsive layouts, text selection, form inputs, and accessibility.
* Phaser is optional. Load it only in screens or experiences that need game-like rendering.
* Use one theme system. Shared color, spacing, typography, and sizing tokens help both renderers look consistent.
* Keep build output generated. Normally, `dist/` and copied Android web assets belong in `.gitignore`; workflows generate them when building.
* Test both targets. A shared source tree improves compatibility, but WebView and mobile browsers can still differ in storage, caching, input behavior, and permissions.
Bundle the web assets into the APK. Don't make the Android app depend exclusively on loading GitHub Pages URL.

...start with `core/`, `components/`, and `renderers/dom/`. Establish the PWA build and verify it on an Android phone. Add `android/` as a thin wrapper using that same build, then introduce `renderers/phaser/` when there is a real use case for it. That avoids building two rendering systems before shared component model is stable.
